# Portfolio position

This file is generated by sdk-forge/forge.py from the portfolio plan, and a hand edit here is
overwritten at the next run. Two documents govern this project and they govern different things:
the obligation table in [../ROADMAP.md](../ROADMAP.md) governs protocol work - which rows exist,
and what evidence closes one - and this file governs sequencing, which is which wave this
project sits in, what has to exist before it can ship behaviour, and what must not be started
while it is unfinished. [PORTFOLIO.md](../../PORTFOLIO.md) at the workspace root is the
authority on both, so a change to a tier, a wave or an arrow is made there and regenerated here,
never the other way round.

## Position

**Tier 2, wave 2** - the first real answer. Tier 2 is next: high value, and each entry needs
something from Tier 1 before it can produce behaviour.

## Depends on

- **asn1core** - an OCSP response is a signed DER object and a CRL is DER all the way down, so a
  revocation answer that cannot be re-derived from the bytes it arrived in is not an answer.
  **Status: does not exist yet.** There is no asn1core project and no asn1core code: the
  workspace holds only its extraction plan at ../../asn1core/PLAN.md.
- **pkix** - deciding whether a responder may sign for a CA is path validation against the same
  trust anchors pkix already resolves, and a second validator here would only disagree with the
  first. **Status: exists only as a generated shell, with no protocol behaviour yet.** Its
  public functions raise NotImplementedError until its own roadmap rows are done, so a row here
  that consumes it cannot be closed on the strength of a directory existing.

A dependency that exists only as a shell is the same gate in weaker form: pkix has a directory,
CI and an obligation table, and no behaviour, so work here can be designed against such a
dependency and cannot be finished against it.

**Blocked, not in progress.** asn1core does not exist yet, so revokekit cannot ship behaviour
until asn1core does. A roadmap row that parses, encodes or verifies a DER structure is not
deferred work here: it is gated on a project that has no code and no test suite. Any plan,
milestone or release note that cites asn1core says blocked rather than in progress, and no
release of revokekit is promised before asn1core has one of its own.

## Sequencing rules

- At most two projects in the portfolio carry real effort at once. A third is not started, and
  no obligation is taken here, while those two are open.
- No new shell is created while any Tier 1 project still has an unimplemented obligation.
  Twenty-eight generated READMEs are already the maintenance liability, and the failure mode of
  this portfolio is prose outrunning code rather than under-building.
- A project freezes to Tier 4 when its first release finds no external user, and a shell is
  retired publicly when a competitor ships what it promised rather than left to rot - the
  retirement is announced, not a README quietly left to go stale.
